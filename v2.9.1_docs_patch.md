## 1. `CHANGELOG.md` — prepend this directly under `# Changelog`

```markdown
## v2.9.1 — 2026-09-22
- DIAGNOSTICS (the "Job update failed: Graph 400 invalidRequest" wall): every
  Graph failure now names the call that failed. `gFetch` throws
  `Graph <status> <code>[/<innerError>] on <METHOD> <url> — <message>` instead of
  dumping the raw JSON body, and writes the same line to the bug log
  automatically. The old message could not tell you whether the folder, the
  upload or the PDF conversion had failed. The `Graph <status>` prefix is kept
  because `gFetchWb` and `odConvertToPdf` test for it to decide what is
  retryable. "Does this exist?" probe GETs pass `quiet: true` so their normal
  404s don't flood the 200-entry bug log.
- NEW: Settings → About → **OneDrive self-test**. Runs the exact same chain
  "Create / Update job" runs — token/scopes, read drive, root folder, child
  folder, small text upload, book-folder name, this FSO's job-folder name, build
  and upload the filled workbook, `?format=pdf` conversion, and the SharePoint
  job folder if the toggle is on — one step at a time, and reports OK/FAIL per
  step with the method, URL and Graph error code. Everything is written into a
  `_selftest` folder, so no job data is touched. The report is copied to the
  clipboard and saved to the bug log.
- FIX (name rules): `sanitizeName` could produce a name OneDrive refuses with a
  bare 400 invalidRequest. It now also strips control characters, `[ ] ^`, any
  trailing full stop or space (OneDrive rejects both, and the 110-character
  slice or a description ending in "…No. 3." created exactly that), any leading
  dot/space, and it escapes the reserved names `CON PRN AUX NUL COM1-9 LPT1-9`,
  `_vti_*`, `~$*` and `forms`.
- FIX (folder creation gave up too early): `odEnsureFolder` and
  `odEnsureChildFolder` looked the folder up, and on any failure tried to create
  it with `conflictBehavior: fail`. A transient error on the lookup therefore
  turned a folder that already existed into a 409 that killed the whole export.
  Both now re-check after a failed create, and report the folder name in the
  error if that also fails.
- FIX (empty/oversize uploads): `odPutFile` refuses an empty parent id, an empty
  file name or a 0-byte body with a plain-English error instead of letting Graph
  answer 400. Uploads over 4 MB are logged (250 MB is the real direct-upload
  limit, so an FSO workbook that big means something is wrong).
- `odConvertToPdf` now takes the file name for its error messages, rejects a
  0-byte PDF, and prefixes failures with `PDF conversion failed for "<file>"`.
- SW cache v24.
```

```markdown
## Diagnosing a Graph failure (read this before guessing)

`gFetch` errors carry everything needed to place the failure:

    Graph 400 invalidRequest/invalidPath on PUT /me/drive/items/<id>:/<name>:/content — <message>

and the same line is appended to the bug log (Settings → Report a Bug). Probe
GETs — "does this folder exist?" — pass `quiet: true` and are not logged; their
404 is the normal path to the create call that follows.

**Settings → About → OneDrive self-test** (`odSelfTest`) walks the same chain as
`createOrUpdateJob`, one step at a time, into a `_selftest` folder:

1. token + account + the scopes actually requested
2. `GET /me/drive` (also shows `driveType` — personal vs business)
3. root folder (`odEnsureFolder`)
4. `_selftest` child folder (`odEnsureChildFolder`)
5. small text upload (`odPutFile`)
6. the book-folder name, and this FSO's job-folder name — proves the names are legal
7. build + upload the filled FSO workbook (`generateXLSXFilled` + `odPutFile`)
8. `?format=pdf` conversion (`odConvertToPdf`)
9. the SharePoint job folder via `/shares/{u!base64url}/driveItem`, if the toggle is on

It stops at the first failure — that is the call to fix. Run it from the FSO
screen's context (open the FSO first) so steps 6–8 use the real job data.

**Name rules that cause a bare 400 invalidRequest** (all handled in
`sanitizeName`, don't re-introduce them): reserved characters
`\ / : * ? " < > | # % ~ & { } [ ] ^`, a trailing full stop or space, a leading
tilde, and the reserved names `CON PRN AUX NUL COM1-9 LPT1-9`, `_vti_*`,
`forms`. Note the 110-character cap on `fsoDocTitle` can itself create a
trailing space — strip after slicing, never before.
```
