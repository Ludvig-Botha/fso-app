## 1. `CHANGELOG.md` — prepend this directly under `# Changelog`

```markdown
## v2.9.2 — 2026-09-22
- FIX (purple blocks on an unsigned FSO): the embedded template's two signature
  placeholders, `xl/media/image3.png` and `image4.png`, were 1x1 pixels of
  RGBA(0, 0, 255, 127) — 50%-opacity BLUE, not the "blank transparent" they were
  described as. Stretched across the anchor block they printed as a solid violet
  rectangle. Both are now 1x1 fully transparent pixels, so an unsigned box
  renders plain white with the template's dashed signature line intact. The
  export path also writes that transparent pixel explicitly every time, so any
  older copy of the template can't bring the purple back.
- FIX (signature stretched): both signature pictures are anchored with
  `<a:stretch><a:fillRect/></a:stretch>` — "stretch to fill the cell block".
  The block measures 252 x 56.4 px (189 x 42.3 pt, aspect 4.47) and a real
  signature is nearer 3:1, so the ink was being pulled ~1.5x sideways. Each
  signature is now letterboxed onto a canvas with exactly the block's aspect
  ratio before it goes into the workbook, so the fill is geometrically neutral
  and the signature keeps its true shape. The block is measured from the
  template on every export (`xlAnchorBoxPx` reads `drawing1.xml` plus the
  sheet's `<cols>` and row heights), so re-anchoring the picture in Excel needs
  no code change.
- FIX (poor signature quality) — three separate causes:
  - the capture canvas was sized in CSS pixels, so on a 3x phone screen every
    stroke was recorded at a third of the resolution it was drawn at. The
    backing store is now sized at `devicePixelRatio` (capped at 3), with the
    context scaled so drawing still happens in CSS pixels.
  - the canvas height was guessed as `overlay.offsetHeight - 120`, which rarely
    matched the flex-sized canvas, so strokes were captured slightly squashed.
    It now measures the canvas's real laid-out box, and re-fits on rotation
    while nothing has been drawn yet.
  - `processSignature` thresholded the alpha channel to 255, destroying the
    antialiasing on every stroke edge — that 1-bit staircase is what looked
    ragged once the sheet scaled the image down. Ink is now forced to black
    while the antialiased alpha is kept (faint edges get a 1.3x boost so they
    survive the downscale), the crop padding scales with capture resolution, and
    the crop copy is 1:1 with smoothing off. Still lossless PNG throughout.
  - net effect: the signature is downscaled, never magnified, and carries
    1.5x-4x the pixels the sheet needs at 96 dpi so it stays sharp when Graph
    renders the PDF at print resolution.
- NEW: signatures can be deleted. A "Delete signature" button appears under each
  captured signature on the FSO screen (`deleteSig`). Deleting the customer
  signature also clears the signed-by name (AE63) and the date signed
  (AE65/AE72) and returns the job to In progress, so the sheet can never print a
  name and date with no signature above them. Both deletions are written to job
  history. Exported PDFs are untouched — the immutable-revision rule is
  unchanged, so the next Create / Update job writes a new revision.
- Verified by rendering the template to PDF before and after: purple blocks gone,
  dashed lines intact, and a 3:1 test signature that measured 1.49x stretched now
  renders at its true aspect.
- SW cache v25.
```

## 2. `CLAUDE.md` — add this section (suggested position: after `## Workbook architecture`)

```markdown
## Signatures — capture to PDF

- **Capture** (`initSigCanvas`): backing store is sized from the canvas's real
  laid-out box multiplied by `devicePixelRatio` (capped at 3); the context is
  scaled by the same factor so all drawing code stays in CSS pixels. Never size
  this canvas in CSS pixels, and never guess its height from the overlay.
- **Post-process** (`processSignature`): ink is recoloured to black with the
  browser's antialiased **alpha kept**. Do not threshold alpha to 255 — that is
  what made signatures look ragged in the PDF. Output is cropped to the strokes
  with resolution-proportional padding, as lossless PNG.
- **Storage**: the cropped PNG (base64) lives in `fso.signatures.customer` /
  `.engineer` in localStorage. Keep it cropped — the box-fitted version is built
  at export time, not stored.
- **Export** (`generateXLSXFilled`): `xlAnchorBoxPx(drawing1.xml, sheet1.xml,
  'sig_customer' | 'sig_engineer')` measures the anchor block in 96-dpi pixels
  (252 x 56.4 px today, aspect 4.47) from the template's own `<cols>` widths and
  row heights; `sigToBoxPng` letterboxes the signature onto a canvas with that
  exact aspect ratio, centred, scaled so the ink is never magnified. The anchors
  use `<a:stretch><a:fillRect/></a:stretch>`, so anything whose aspect ratio
  differs from the block gets distorted — this is why the letterbox exists.
- **Unsigned**: `BLANK_SIG_PNG_B64`, a 1x1 fully transparent pixel, is written
  to both media parts. Never put a coloured or semi-transparent pixel there —
  the template originally shipped RGBA(0,0,255,127), which printed as a purple
  block across the whole signature box.
- **Template media map**: `image1.jpeg` = ACTOM logo, `image2.png` = John
  Thompson logo, `image3.png` = customer signature, `image4.png` = engineer
  signature. Named picture anchors: `actom_logo`, `jt_logo`, `sig_customer`,
  `sig_engineer` — the export code looks them up by name, so keep the names if
  you rebuild the template.
- **Deleting** (`deleteSig`): customer delete clears the image, the signed-by
  name and the date signed, and reverts status `signed` -> `progress`. Never
  touch an exported PDF; a re-export becomes a revision.

### Still stretched, if you want it fixed later
The two logos use the same fill anchors, so they are stretched by the same
mechanism: ACTOM artwork 6.34:1 in a 7.69:1 block (1.21x wider), John Thompson
3.43:1 in a 4.47:1 block (1.30x wider). The same `xlAnchorBoxPx` +
letterbox pass would fix both without touching the template.
```
